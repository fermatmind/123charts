# 新地址克隆与本地启动验收（2026-10-22）

从 `https://github.com/fermatmind/123charts.git` 实际克隆独立副本，使用锁文件安装依赖，再对当前修复完成初始化、预览与重启验证。环境为 macOS Apple Silicon、Node 20.20.0、npm 10.8.2、Docker 29.1.2；Node 24 为 `.nvmrc` 建议版本，不把本次 Node 20 实测写成其他平台已验证。

## 发现与修复

- README 原来写死开发者本机路径；改为新地址 clone、相对目录、`npm ci`，说明 Node/Docker 要求、随机账号、本地环境生成与常用入口。
- 启动/停止脚本固定使用默认项目名；现在从 `supabase/config.toml` 读取实例、端口和 Web URL。启动前识别容器所属目录、保留卷的本地归属记录、远程环境和端口冲突，避免另一份克隆复用原数据库。
- 空库运行中，重新绑定 PostgreSQL 会终止 Auth 持有的连接。原重启后的首次登录实际遇到 SQLSTATE `57P01`，Auth 返回 500；密码与数据库内容未变。修复为重连当前实例的 Auth/REST/Storage/元数据依赖，并等待 Auth 与资料接口就绪后再启动 Web/worker。
- 临时数据库测试原来固定定位默认容器并依赖 `rg`；改为当前实例，移除这项额外命令依赖。
- 增加不连接运行数据库的 `test:unit`，区分写入型接口/浏览器集成检查。构建前停止当前 Web/worker，避免开发与构建共用 `.next`。

## 隔离与边界

测试使用独立 `123charts-clean-check` 项目、`5532x` 端口和 Web `3101`；该端口配置仅用于验收，不提交，仓库默认仍为 `123charts-local` / `5432x` / `3100`。测试实例停止后保留数据卷，原有 3100 预览继续运行。原实例的项目、申请/草稿、认领、关系和报告在前后逐字段比较中保持一致。

原始日志与截图保存在本机忽略的 `.local/`、`output/playwright/`，不提交账号、环境值或数据库快照。原生 Windows、Linux/WSL 和全新镜像下载网络未逐个平台实测；本机首次 npm 安装已实际执行，Supabase 镜像复用本机缓存。没有服务器部署、DNS 修改或生产数据操作。
