# 123Charts 导航页面结构与交互重构规范

**日期：2026-10-22｜对象：123charts.com 公共前台｜用途：产品、设计与 Codex 实施共用**

## 0. 本轮定版

首页采用“紧凑搜索＋常用直达＋分类网站地图＋有限新发现”的结构。网站名称直接打开官网；简介、替代、收藏提供独立操作。分类和个人常用保持位置稳定，轮换集中在固定的小区域。

本规范覆盖上一版全站架构中公共首页、导航列表、搜索及替代页的展示与交互约定。既有项目身份、投稿、审核、公开状态、认领、关系审核及冻结首次公开时间继续复用。本文是经现场观察形成的设计规格，不是改版已完成或效果已验证的报告。

产品范围：免费浏览、免费提交、免费正常审核与基础收录；首次主动投稿提供 3–5 个相关同行候选。首版不做第三方网站访问量排名、截图 OCR、复杂投票或付费买名次。

## 1. 现场观察与证据边界

本轮通过连接浏览器实际打开用户提供的本地首页，并读取和截图以下页面。日期为 2026-10-22。没有依据截图中的其他开发窗口断言后端测试、提交或部署结果。

| 步骤 | 观察的页面/动作 | 实际结果 | 设计判断 |
| --- | --- | --- | --- |
| 1 | 首页 /zh?dataset=real | 大标题、介绍、搜索与三类入口在前；本期发现混合不同任务的网站；网站名称链接进入详情，另有官网按钮 | 主要入口出现过晚，分类未直接交付网站选择 |
| 2 | 点击 AI 编程辅助分类 | 分类页正常打开；有四视图、筛选、十个项目；默认“发现轮换”；有双语重复及测量范围文案 | 已有分类与资料可复用，需要压缩信息并稳定基础导航 |
| 3 | 首页输入 n8n 并搜索 | 进入 /zh/projects?q=n8n&dataset=real，返回一个匹配项目；仍使用通用发现页标题、轮换说明与行组件 | 精确找网站可以提供更直接的入口，避免套用发现说明 |
| 4 | 查看 Activepieces 替代页 | 展示一个 n8n 候选及任务、条件、来源说明；大段中英双语研究文案同时公开 | 已有关系数据可转为结构化差异，不需要重新建比较系统 |

首页一次观察的浏览器视口为 2148 × 1152 CSS 像素，首个“官网”链接顶部约在 y=764，完整可见的项目名称区为 Cursor、n8n、Haystack 三项。该数字只描述本轮视口，不代表所有屏幕；后续改版应在相同视口复测。

已观察到项目名“ AWS · whole website ”及“测量对象为整站”等旧资料表达。应核实条目究竟指网站平台还是具体产品，再修正公开名称、用途和官网落地地址；不能只换名称而保留不对应的地址。

本轮未核验：所有筛选组合、真实账号同步、投稿发布、后台事件去重、全站无障碍与真实用户转化。因此本文的留存和密度数字均为设计目标或待验证假设。

## 2. 第一性原理：从用户任务推到界面

不把某种配色、卡片样式或链接数量当成必然正确。先确定每次访问必须完成的动作，再决定页面结构。

访客的任务有三种：
1. 已知网站：辨认名称，然后到达官网。
2. 只有任务：找到相关分类，理解几个候选，再选择官网。
3. 想换网站：确定替代目标和用途，比较差异，再选择官网。

首版优化的是“找到位置＋理解用途＋判断条件＋完成操作”的总成本，不能只把链接堆多，也不能强迫所有人先读介绍再访问。

| 角色 | 真实需求 | 页面决策 |
| --- | --- | --- |
| 普通访客 | 快速到达合适网站，需要时有比较依据 | 稳定分组、清楚名称、短用途、官网直达、按需详情 |
| 创业者 | 零金钱提交成本、相关曝光和可核对反馈 | 免费提交、公开条目、相关替代入口、有限新人/贡献位置 |
| 平台 | 有用的访问与回访、持续完善的资料 | 常用区、稳定导航、收藏与关注、项目维护、基础事件反馈 |

公共首页优先服务找网站的人。项目方的入口放在顶部，效果数据放在工作台，审核和调度规则放在后台或规则页。三方都得到价值，但不需要各占首页三分之一。

品牌 Charts 继续通过分类列表、新收录和有明确定义的后续榜单体现。页面出现编号时必须说明依据；导航位置不包装成全球实力或访问量名次。

## 3. hao123 与 265 的参考结论

本轮读取 hao123、hao123 移动网址大全和 265 官方页面，并在浏览器查看 hao123 首页。可观察到搜索、网站名称集合、按类别分组、更多入口等结构。[S1][S2][S3]

值得借鉴：
- 把可点击的网站直接放在首页。
- 类别名称提供上下文，用户可扫描选择。
- 熟悉的网站用紧凑名称表达。
- 分类内“更多”承接完整目录。
- 常用入口形成重复使用的起点。

123Charts 的设计取舍：
- 保留用途解释，因为新创业项目通常不能仅凭名字理解。
- 增加任务相关的替代比较，这是与普通网址集合不同的核心价值。
- 首版不扩展新闻、天气、行情或无限内容流等额外业务。
- 新人和贡献推荐只占有限位置，不能不断重排用户熟悉的导航。
- 替代目标、价格条件和相关性来自已有公开资料，不能从版式推断质量或名次。

这些是本项目的推导与设计选择，不是已证实的增长效果。

## 4. 全站页面职责与现有路由

已有等价页面优先复用，尤其现有 /projects 搜索结果与 /following 收藏入口，不能为了匹配方案文字额外复制一套。

| 页面 | 新的主要职责 | 主要操作 |
| --- | --- | --- |
| /[lang] | 分类网站地图、常用直达、有限新发现 | 打开官网、定位分类、找替代、加常用 |
| /[lang]/categories | 全部分领域与任务分类 | 选择类别 |
| /[lang]/categories/[slug] | 当前分类的完整导航与精简条件比较 | 筛选、打开官网、简介、替代 |
| /[lang]/projects?q=... | 现有搜索结果页 | 精确匹配、相关任务、官网直达 |
| /[lang]/alternatives | 输入或选择目标网站 | 进入已有目标替代页 |
| /[lang]/alternatives/[slug] | 围绕目标与任务选择替代方案 | 对比差异、官网直达 |
| /[lang]/products/[slug] | 一个项目的详细公开档案 | 理解使用条件、官网访问、认领与纠错 |
| /[lang]/new、/free、/open-source | 同一目录的专题视图 | 新收录、免费条件、开源属性 |
| 现有收藏/关注页面 | 管理自己的常用、收藏与关注 | 排序、移除、查看更新 |
| 现有提交与项目工作台 | 投稿、资料维护、反馈 | 提交、修订、分享 |
| 现有运营后台 | 审核、关系、分类、展示管理 | 复用当前权限与状态逻辑 |

首页不显示大型公共侧栏。当前仅三类时，用分组和简短锚点即可。分类逐渐增多后，可以增加窄的分类定位栏，但不重复顶栏或个人工作台菜单。

## 5. 桌面首页结构

### 5.1 从上到下

| 顺序 | 区域 | 默认内容 | 交互 |
| --- | --- | --- | --- |
| 1 | 紧凑页头 | Logo、全部分类、找替代、我的常用、免费提交、语言/账户 | 公共入口清楚分工 |
| 2 | 单一主搜索 | 找网站 / 找替代，两种明确模式 | 输入、选择建议或提交搜索 |
| 3 | 精选直达 / 我的常用 | 新访客看少量编辑选择；有收藏后显示自己的常用 | 名称直达、固定、编辑 |
| 4 | 新发现 | 最多一行的新人或有效贡献项目，建议初始 3–4 个 | 官网、简介；区域有明确性质 |
| 5 | 分类网站地图 | 按任务分组的网站名称、短用途与辅助动作 | 直达官网、简介、替代、分类更多 |
| 6 | 找熟悉网站的替代 | 仅展示已经有内容的目标入口 | 进入目标替代页 |
| 7 | 简短页脚 | 规则、关于、纠错、免费提交 | 辅助信息 |

第 3 区没有收藏时叫“精选直达”，不能声称是用户自己的常用，也不能将人工选择称为真实流量排行。常用区只展示有限数量，其余通过“更多”进入现有收藏页。

第 4 区位置固定、面积有限，不做自动播放轮播，不让新项目依次抢占整个首屏。候选不足时缩短区域或补入已公开且相关的普通候选，并如实表达区域性质。

### 5.2 分类地图是首页主体

桌面建议每组采用“类别标签＋网站网格”。一个类别可先展示 6–8 个网站，超过部分由“更多”进入分类页。默认可用四列、两行的紧凑站点单元；不把每个网站画成大型独立卡片。

站点单元只承担两行信息：
- 第一行：小图标、网站名称、添加常用操作。
- 第二行：短用途、简介、替代入口。

网站名称是主动作。短用途帮助用户理解陌生项目；辅助入口视觉较轻但可见。详细价格表、研究依据和更新时间留给分类比较、替代页或详情页。

当前资料先支撑现有三类：
- AI 编程辅助：编写、审查与理解代码。
- 知识库与检索开发：现有知识搜索/RAG 分类应按真实项目用途表达，不把向量数据库泛称成普通“查资料”工具。
- 工作流自动化：连接应用与执行流程。

全行业是目录扩展方向，可以逐步增加办公、创作、学习、营销、生活服务等领域。首页只展示有足够公开内容的分类，不能用空分组伪造覆盖。

### 5.3 尺寸是初始设计参数

| 参数 | 建议起点 |
| --- | --- |
| 主内容宽度 | 桌面约 1200–1280 px，窄屏随视口收缩 |
| 页头高度 | 约 56 px |
| 搜索区高度 | 约 64–72 px，含间距 |
| 主体文字 | 14–16 px；网站名称优先 15–16 px |
| 短用途/辅助文字 | 约 12–13 px，需实际检查阅读性 |
| 普通站点单元 | 约 52–64 px 高，长名称自然换行 |
| 主色 | 浅色底、深色文字、一个稳定强调色；可保留深色选择 |
| 分隔 | 以对齐、留白和细分隔线分组；避免大阴影和层层卡片 |

建议在 1440 × 900 视口试做首屏 18–24 个不同项目入口；在 390 × 844 视口先检查 6–10 个入口。这是布局测试目标，受真实内容和可读性约束，不能为凑数缩小文字、复制项目或隐藏必要条件。

## 6. 全站点击规则

| 元素/操作 | 结果 | 必须一致的细节 |
| --- | --- | --- |
| 网站名称、小图标 | 打开已维护的官网地址 | 公共导航列表统一，外链有清楚提示 |
| 简介 | 进入站内项目详情 | 使用真实内部链接 |
| 找替代 | 进入该网站已有内容的替代页 | 没有关系时不伪造有内容入口 |
| 添加常用 | 保存当前项目 | 不能触发官网跳转 |
| 分类标题/更多 | 进入完整分类页 | 保留语言与适用筛选 |
| 分类锚点 | 定位本页分组 | 不必绕到新页面再返回 |
| 网站名悬停 | 可选短提示 | 不抢焦点，不覆盖主点击区 |
| 键盘焦点 | 明确显示当前动作 | 简介、替代、常用均可键盘操作 |
| 手机更多操作 | 打开辅助操作面板 | 不能以长按或悬停为唯一入口 |

官网可以在新标签打开并标注，保留目录位置；站内页面正常导航并支持返回恢复滚动和筛选。不要使用覆盖整个单元的大链接把辅助按钮包进去。

每个项目的替代入口按实际情况呈现：
1. 有已接受且公开的候选：显示“替代”。
2. 暂无候选：可显示明确的“查看同类”，指向分类；不伪装成已完成的替代榜。
3. 只有一个有用候选：如实展示一个，不凑“Top 10”。

名称直达不取消项目档案。简介、替代、分类与详情仍通过可抓取的真实链接相互连接。公共目录的基础内容直接输出页面 HTML，不依赖登录或必须操作聊天才能看到。

## 7. 搜索：明确意图，再减少步骤

### 找网站模式

输入产品名、域名或任务时，给出精简建议：
- 项目匹配：网站名称、短用途、官网动作。
- 相关分类：按任务进入。
- 相关替代入口：存在时提供。

用户选择明确的官网动作，直接打开官网。仅输入文字后按 Enter、且没有主动选中某个建议时，进入现有 /projects 搜索结果；不擅自把第一个候选当成用户确定的目标。

精确匹配结果置前，采用清楚标题，例如“找到 n8n”；页面不再解释每日轮换，也不把商业推荐插到精确结果前。

### 找替代模式

先识别目标网站，再展示其相关替代选择。必要时选择具体任务。找不到目标时，提供相近项目与分类；没有已确认候选时如实说明，并给出同类浏览入口。

### 搜索公共规则

- 首页只突出一个主要搜索框；顶部快捷键入口可以聚焦该搜索或打开同一个搜索组件。
- 搜索与筛选保存在 URL，返回时恢复。
- 空结果显示已选条件、清除条件和相近分类。
- 按钮使用“搜索”或“找替代”，不用含糊的“开始发现”承担不同意图。
- 首版使用现有搜索和字段匹配即可，不要求引入新模型调用或搜索平台。

## 8. 分类页结构

顺序：面包屑＋分类名称及一句用途 → 一条精简筛选 → 紧凑网站列表 → 分页或更多。

默认导航保持稳定，排序可以明确提供“默认顺序”“新收录”“名称”。免费、免费试用、开源分别处理；未知价格只在对应字段说明，不当作免费。

推荐单行/紧凑行：
网站名称与官网域名｜一句用途｜必要价格条件｜简介｜替代｜常用。

当用户需要比较时，使用已有字段展开价格范围、支持语言、使用限制；不要让每项默认展示一整段中英双语研究记录。

分类的新人/贡献区与基础列表分别呈现。基础列表不因推荐周期、点击或贡献重新洗牌；运营调整要有明确原因，例如纠错或分类归并。

## 9. 替代页结构

页面首先回答：“你在什么用途上想替代这个网站？”

| 区域 | 内容 |
| --- | --- |
| 顶部 | 目标名称、短用途、目标官网入口 |
| 条件 | 当前任务、价格方式、语言等必要条件 |
| 对照列表 | 候选、适合谁/适用任务、关键差异、使用条件、官网 |
| 辅助 | 简介、收藏或关注专题 |
| 依据 | 来源、更新日期、详细解释，可按需展开 |

关键限制必须在对应候选附近可见，例如“云端仅试用”“需要自行部署”；资料来源的长段落可以展开。中文页优先中文，英文页优先英文，不能两种语言重复占据每一行。

当前 Activepieces 替代页已经有任务、条件和说明，可以重排成短字段，不需要从零另建比较器。一个目标只有一个候选时照实展示，不以增加页面数量为目标。

“用途相关”“功能等价”“完全可替代”是不同判断。关系只在已确认任务上成立。界面以“在任务 T 上可考虑”表达，不给所有创业者自动发放“最佳替代”认证。

## 10. 项目详情与提交页

项目详情承担深入理解，结构为：
名称/官网 → 一句话用途与适用对象 → 价格和使用条件 → 关键能力与限制 → 同类与替代 → 来源、更新、认领/纠错。

官网按钮在顶部，用户不必读完整页才可以离开。项目方统计继续位于有权限的工作台。

提交保留三步：
1. 官网 URL 与重复识别，已有档案走认领或资料修订。
2. 确认用途、分类和必要使用条件，预填字段可人工修正。
3. 提供 3–5 个同行候选，支持名称匹配与批量粘贴。

提交后展示预览和处理状态。项目公开后才提供正式收录卡；关系分别审核。基础收录持续免费，分享自愿，普通资料维护不要求重新完成首次同行任务。

## 11. 常用区与回访

### 首版复用收藏

“我的常用”是现有收藏在首页的展示窗口，不建设第二套独立收藏后台。首页显示有限数量，更多进入现有收藏页。

游客可以先将项目 ID 保存在当前浏览器，并明确“仅保存在此浏览器”；登录用于跨设备同步。不得先弹出登录墙才允许第一次保存常用。

登录时：
- 按稳定项目 ID 去重。
- 保留账号已有顺序，把匿名新增项追加。
- 账号内容未被显式选择前，不覆盖为游客顺序。
- 合并成功后标记已合并或清除待合并记录，避免删除后再次登录又恢复。
- 退出账号后清除该账号在界面的私人数据，不自动转入游客常用或另一个账号。

允许用户明确调整自己的常用顺序。实现可先用上移、下移和移除，拖拽作为增强。项目停止运营时提示状态，不能偷偷换成另一个项目。

### 两类回访分别服务

- 重复使用：常用入口，记住位置，直接到达。
- 持续发现：关注分类或替代专题，回来看相关新增。

项目方回访主要看处理状态、实际展示和官网点击，并维护资料。不通过无关通知制造回访。

## 12. 曝光与贡献

| 位置 | 是否轮换 | 规则 |
| --- | --- | --- |
| 我的常用 | 不自动轮换 | 用户决定顺序 |
| 分类基础导航 | 保持稳定 | 公开且相关，必要更新有原因 |
| 新发现 | 有限轮换 | 固定区域、同一周期稳定、单项目占位封顶 |
| 贡献推荐 | 有限轮换 | 有效资料/纠错/关系被采纳后，增加有上限的机会 |
| 替代页 | 先满足关系与用途 | 不因提交次数或提到巨头就获得推荐 |
| 赞助，后续 | 单独安排 | 独立标记，不改变普通结果与个人常用 |

首版可试行同一访客在同一天看到同一组新发现；基础导航长期稳定。随机只用于符合相关条件的候选之间，不跨行业混塞。刷新页面不重新抽取一整页。

排序排期、实际可见曝光、主动官网点击分别统计。用“获得一次排期”不能冒充“用户已经看到”。贡献规则和单周期上限可配置，不需要先建设复杂积分体系。

增加推荐位不能凭空增加注意力。平台给项目方的是相关展示机会和真实反馈，不承诺免费提交必得访问量或全球名次。

## 13. 移动端

- 顶部保持 Logo、搜索入口和免费提交；主要搜索与分类定位易于触达。
- 站点按两列或紧凑单列显示，长名称自然换行。
- 网站名称首次点击仍然直达官网，不能改成第一次展开、第二次才访问。
- 简介/替代/收藏可使用清楚的更多操作按钮，不依赖悬停。
- 常用、分类主体、新发现保持同样优先级，不把多个大型模块藏进横向轮播。
- 触控目标建议按约 44 px 设计；这是本项目设计目标，最终需在真实设备检查。
- 不采用强制全页横向滚动的比较表；必要时把候选变成有相同字段的竖向行。
- 筛选、返回位置和用户已输入内容都要保留。

## 14. 最小实施拆分

优先复用现有代码与路由，只调整公共布局和共用组件：

| 顺序 | 工作项 | 交付 |
| --- | --- | --- |
| P0-1 | 压缩首页介绍和重复搜索，明确点击规则 | 一套清楚的站点单元 |
| P0-2 | 首页改为分类分组的网站直达地图 | 当前三类已有内容直接出现 |
| P0-3 | 分类/搜索/替代页共用紧凑信息层级 | 不同意图拥有正确默认动作 |
| P0-4 | 清理重复双语、轮换标签和流量研究遗留文案 | 公开信息面向使用决策 |
| P1-1 | 复用收藏做常用区，加入游客本地保存与一次性合并 | 回访路径可用 |
| P1-2 | 小范围新发现/贡献推荐，接现有事件记录 | 稳定导航和有限曝光共存 |
| P1-3 | 移动端、键盘与返回状态核对 | 主要路径一致 |

建议组件职责：
- 公共紧凑页头与统一搜索。
- 站点单元：名称外跳、简介、替代、常用。
- 分类分组：类目与有限站点集合。
- 常用区：复用收藏及其顺序。
- 新发现区：固定位置与周期候选。
- 替代比较行：读取现有任务、差异和条件。
- 私有统计：复用实际曝光与主动官网点击事件。

不为改版另建数据库、用户体系、审批系统、Agent 平台或推荐服务。首页的数据是既有公开资料的另一种组织形式。

## 15. 验收与测量

### 页面验收

1. 已知网站：在可见入口点击名称，一次操作打开正确官网。
2. 知道任务：可以在首页对应分组直接选网站，不必先经过分类、详情两层页面。
3. 想找替代：选择目标后看到具体任务、差异和条件，能访问候选官网。
4. 常用：游客保存后刷新仍在；重新进入位置不变；账号合并不复活已删除条目。
5. 分类：刷新不会整体洗牌；换筛选和返回保持状态。
6. 关系：没有已确认候选的项目不伪装成有内容的替代入口。
7. 数据：免费、试用、开源分别表达；未知不推断为免费；旧测量口径不充当用途。
8. 点击：简介/替代/收藏不会误触官网；统计失败不阻止外跳。
9. 可读：中英文分别测试长名称，站点描述不覆盖动作；键盘能到达辅助入口。
10. 改版前后使用同一视口比较首个网站入口位置与可读站点数量，另核验一个手机视口。

### 经营观察

首期观察：
- 已知网站任务从打开首页到触发官网访问的时间。
- 包含主动官网点击的访问会话比例。
- 加入常用后七天内再次使用的访客比例。
- 替代页产生的主动官网点击。
- 新发现区实际可见曝光及点击。
- 无结果搜索与错误官网反馈。

这些是观测指标，不预设一定提升。官网点击只能说明平台内用户主动外跳，不等同于对方网站独立访客、注册或成交；游客统计按可识别浏览器口径解释。

## 16. 给 Codex 的执行摘要

目标：将现有 123Charts 公共前台重构为 hao123 式的紧凑分类导航，并保留任务替代价值。

先阅读真实仓库与当前页面。以本规范覆盖旧版公共首页和列表交互，不新建一套项目。优先完成首页、统一站点单元、分类与搜索，然后接常用区和有限新发现。

关键规则：名称打开官网；简介进入项目页；替代进入有内容的目标页；分类/常用稳定；轮换只在独立区域；游客能先保存常用；公开条目继续使用现有审核和关系状态；首版仍为免费提交＋3–5 个同行，无截图任务。

交付应包含改版前后同视口截图、主要路径实测结果和真实剩余缺口。不要仅以 build 通过或模块已存在作为页面目标完成的依据。实施范围与部署方式按用户对当前开发窗口的授权执行。
