# 认领与资料更新：本地实走记录（2026-10-22）

本轮仅修改现有前端及操作提示，无 migration、生产配置、push 或部署。复用 127.0.0.1:3100 的现有项目服务及 127.0.0.1:54321 的本地 Supabase。

## 已实际走通的路径

在独立 Chrome 浏览器会话中分别以项目方和管理员操作，项目方使用 390×844 手机视口，管理员检查 1440×900 桌面布局。除初始演示项目建档外，认领、两类审核、上传和提交均通过真实页面操作，没有直接写入已通过的认领状态。

1. 未登录时从项目认领入口登录，返回同一项目和认领表单。
2. 填写认领依据并提交，显示“认领申请已提交，等待管理身份审核”和工作台入口。
3. 工作台显示项目名、认领状态；待审时更新表单仍被阻止。
4. 管理员在认领页确认管理身份；项目方刷新工作台后获得更新入口。
5. 打开 AI 辅助说明，复制提示词；实际读取浏览器剪贴板，核对官网和 JSON schema。
6. 上传带 Markdown 围栏的错误 JSON，获得明确的格式反馈；随后上传合法演示 JSON，确认事实后导入。
7. 保存并刷新，简介、条件和来源依据仍然保留；URL 带草稿 ID。资料更新无需重做同行任务。
8. 从用途与条件步骤点击“提交资料更新审核”，得到真实已提交状态及当前公开档案入口。
9. 管理员要求补充，项目方收到具体反馈并修改中文简介，再次提交。
10. 审核前另一个浏览器标签读回公开页，仍为旧简介；管理员“通过资料更新”后，项目方查看公开页，显示新简介及已认领状态。
11. 数据库读回：同一份更新申请为 approved，同行为 0，来源依据为 1 条；价格未核实（false），首次公开时间保持原值。新关系未被自动创建或确认。

## 操作说明

项目方：简介或站点单元的“认领” → 提供管理关系依据 → 等待身份审核 → 工作台“更新资料与同行” → 展开 AI 辅助说明 → 复制提示词给自己的可联网 AI → 核对来源并保存 JSON → 上传或粘贴 → 勾选确认 → 导入草稿 → 检查表单 → 提交资料更新审核。

上传只是读取 JSON，导入只是填入草稿，提交才进入审核，通过后才覆盖公开资料。资料更新的同行维护为可选。错误 JSON 提供可读提示，文件最大 64 KB；格式和官网域名受现有解析器校验。自动保存完成后刷新会恢复同一草稿。

管理员：认领审核仅确认管理权限；资料审核另外检查项目简介及来源，价格核实单独勾选。按钮名称区分“确认管理身份”和“通过资料更新”，已处理的认领禁止重复点击。
